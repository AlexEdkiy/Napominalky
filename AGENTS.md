# Napominalky

Продукт: local-first заметки, задачи/списки покупок, напоминания и календарь.
Mobile хранит данные в SQLite/Drizzle, backend Laravel обслуживает API/sync,
web Vue — личный кабинет и админку. Сохранность данных важнее новых UI-фич.

## Начало работы

- Прочитай `docs/DEVELOPMENT.md` (текущий фокус, проверки, передача работы),
  актуальную задачу в `docs/TASKS.md` и стандарты только затронутого слоя.
- `CLAUDE.md` и `.claude/agents/` описывают команду Claude; они не запускают её
  в Codex. Используй доступные инструменты сессии, не имитируй вызовы TaskCreate.
- В одиночной сессии координатор может реализовывать и проверять задачи сам.
  Самопроверка должна быть названа самопроверкой, а не независимым ревью.
- При расхождении старого регламента с этим файлом и `docs/DEVELOPMENT.md`
  используй эти актуальные правила работы. Историю задач не переписывай.

## Работа с репозиторием

- Основная копия `/home/vselug/workspace/Napominalky/backend` подключена к
  работающему `reminders_serve`, а `web/dist` — к `reminders_web`.
  Разрабатывай в отдельном worktree; не собирай web в обслуживаемый каталог.
- Merge в основную копию с backend-изменениями является фактической выкладкой.
  Сначала подготовь проверяемый diff и план выпуска; учитывай разрешение
  пользователя на конкретную выкладку. Обычные локальные исправления выполняй сам.
- Сохраняй текущие API-контракты и семантику SQLite/outbox/LWW/tombstone.
  Новые контракты и схемы сначала опиши как отдельное архитектурное решение.
- ID резервируй в TASKS.md перед работой. У реестра один автор на цикл;
  счётчики означают последний выделенный ID, статусы — фактическую готовность.
- Проверки выполняй из своего worktree. `docker exec reminders_app` проверяет
  основную копию, а не твою ветку: нельзя использовать его как доказательство
  проверки изменённого backend. Для backend ветки нужен отдельный контейнер.
- Коммиты: `[TASK-ID] описание`, без force push, rebase и изменения общей Git identity.
  В отчёте указывай ветку, SHA/рабочий diff, проверки, ограничения и следующий шаг.
