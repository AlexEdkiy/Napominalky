# MOB-70 — профиль, настройки и поиск в мобильном приложении

Ветка `manage-2026-09-30`. Подготовлен preview 1.0.3; исходный SHA, CI и APK
будут записаны после сборки. Самопроверка автора, не независимое ревью.

## Исправления

Профиль раньше запрашивался только при старте и не повторялся после сетевой ошибки;
экран не использовал серверное поле `avatar`. Теперь имя/фото обновляются при старте,
возвращении сети/приложения и открытии профиля. Офлайн используется кэш профиля
в SQLite, привязанный к владельцу локальных данных; выход/смена аккаунта удаляет его.
Авторизованный пользователь без загруженного профиля видит «Аккаунт» и повтор загрузки,
а не «Гость». Ответы предыдущей сессии и её запоздалый 401 не затрагивают новую сессию.
API и срок жизни токена сохранены, фото читается из существующего `UserResource.avatar`.

Sync UI и движок теперь используют одно условие: авторизация, разрешение аккаунта,
завершённая загрузка настроек и включённый локальный переключатель. Сохранённый OFF
сохраняется при обновлении профиля. Ни ручное обновление, ни фон, ни выход из аккаунта
не обходят переключатель. OFF отменяет текущий HTTP-запрос, запрещает следующие
батчи/страницы/повторы и применение устаревшего ответа. Очередь и новые правки
сохраняются; ON возобновляет обмен. Уже принятый сервером запрос отменить задним числом
нельзя, поэтому повтор оставшегося outbox использует прежнюю идемпотентную/LWW семантику.
При недоступности сервера OFF действует локально, ошибка обновления настройки аккаунта
показана явно. Выход с неотправленными правками сохраняет прежнее подтверждение удаления.

Переключатель «Уведомления» теперь отменяет запланированные локальные сигналы и блокирует
новое планирование/foreground-показ. ON восстанавливает будущие невыполненные напоминания
и пункты. Отказ ОС оставляет настройку выключенной с объяснением. Поздно завершившееся
планирование после OFF отменяется. Название без «Push» соответствует реализованным
локальным уведомлениям. API сверено с установленным SDK и
[Expo Notifications 54](https://docs.expo.dev/versions/v54.0.0/sdk/notifications/).
Большой аватар хранится вместе с локальными данными, а не в ограниченном по размеру
[SecureStore](https://docs.expo.dev/versions/v54.0.0/sdk/securestore/).

Лупа главной сразу открывает общий экран поиска. Отдельного шага «Искать везде» и
поиска только по заголовкам на главной больше нет. Общий SQLite-поиск охватывает
задачи, покупки, пункты/комментарии, заметки и напоминания по названиям и тексту;
поиск внутри остальных разделов сохранён. Поле общего поиска получает фокус.

## Проверки

- `npm run typecheck` — успешно.
- `npm test -- --runInBand` — **103 файла, 1148 тестов** успешно.
- Реальные sync engine/push/pull/stores/репозитории и SQLite/Drizzle: локальный OFF
  при серверном ON, незагруженные настройки, офлайн, ручной force, повторное ON,
  501 запись/отмена следующего батча, новая правка во время запроса, backoff/cancel,
  выход/смена аккаунта во время pull, курсоры, поля для UI и single-flight.
- Реальные хуки профиля/настроек и SQLite-кэш: офлайн-старт, повтор при возврате сети
  и foreground, новое фото, запоздалые ответы профиля/настроек/401, изоляция владельца.
- RN-компоненты: имя/аватар/fallback, авторизованный аккаунт без данных, гостевой режим,
  прямой переход с лупы главной в глобальный поиск. Существующие интеграционные проверки
  общего поиска, возврата к результатам и работы без сети прошли.
- Уведомления: OFF, оба типа сигналов, восстановление будущих записей из SQLite,
  отказ разрешения ОС, отключение во время native scheduling и текущий foreground-флаг.
- Проверены привязки темы к ThemeProvider и PIN/биометрии к LockProvider/useAppLock;
  существующие регрессии appLock/LockProvider прошли. Настройки и профиль учитывают тему.
- `git diff --check` — успешно. HTTP, native-модули, системные разрешения и навигация
  в автоматических тестах заменены заглушками; бизнес-логика и SQLite выполняются реально.

## Выпуск и приёмка

Android export, CI, EAS archive и APK пока проверяются. Native-зависимости, SDK и схема
БД не меняются. Production web/backend в этой задаче не выпускаются.

Подключённого телефона/эмулятора нет. После установки APK поверх 1.0.2 (44) проверить
имя/фото, OFF → локальная правка → ON, OFF/ON уведомлений с будущим сигналом, поиск
текста пункта/заметки с главной. Реальная доставка Android и биометрический датчик
остаются проверкой на устройстве.
