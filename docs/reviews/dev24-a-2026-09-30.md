## Изменения

- `SyncSerializer` возвращает `note.color`, а для пункта списка — `quantity`,
  `deadline`, `reminder_at`, `link`, `comment`, `tags`. Форматы совпадают с REST:
  deadline — YYYY-MM-DD, reminder_at — ISO UTC, tags — прежняя JSON-строка.
  Добавление полей сохраняет v1; маршруты, whitelist и правила LWW не меняются.
- `BaseRepository.insert/update/softDelete` записывают доменную строку и полный
  outbox snapshot через один transaction writer. Callback синхронный; `.all()`
  выполняет доменный запрос, `.run()` — enqueue до commit. Ошибка откатывает обе
  операции. Публичные методы сохраняют Promise-интерфейс.
- `resetLocalData` синхронно удаляет все семь таблиц в одной транзакции, включая
  ранее пропущенные `shopping_list_item_comments` перед их родителями. Отмена
  уведомлений начинается только после commit. При ошибке DELETE данные и очередь
  восстанавливаются, отмена уведомлений не вызывается.
- Новых зависимостей и миграций нет. Существующие unit-моки обновлены для синхронных
  Drizzle builders; отдельные интеграционные тесты проверяют реальный rollback.

SQLite-тесты применяют все текущие SQL-миграции к `node:sqlite` и используют
**установленный Expo Drizzle 0.38.4**, адаптируя только мост prepared statements.
SQL-триггеры вызывают отказ enqueue для create/update/delete и отказ последнего
DELETE при reset. Проверяются сохранение прежней очереди/строки, полные snapshots,
отсутствие outbox при несуществующей сущности/ошибке доменного INSERT и удаление
комментариев. Это настоящий SQLite, но не нативный Expo на телефоне и не crash-тест.
Тестовый адаптер требует Node >=22.16; CI уже использует Node 22.

Backend запускался с кодом **этого worktree**, read-only vendor исходной копии,
временными storage/cache и отдельным PostgreSQL 17 в сети `napominalky_stage`:
`DB_HOST=db`, `DB_DATABASE=reminders_test`. Реальные DB/Redis не использовались.
PHP runtime: `sha256:88507808a3030b6fed3e9b41290db2b9022ff09772446317e17df2be364cfd3e`.
Первый тестовый контейнер не запустился из-за отсутствия vendor mountpoint; после
его создания проверки заработали. Предупреждения о read-only Pest cache и отсутствии
.env устранены tmpfs и локальной `.env.testing` с фикстурным ключом; полный прогон чистый.
Для доказательства регрессии старый serializer отдельно подставлялся read-only mount,
не заменяя рабочий файл. Исходный SQLite-прогон сделан до изменений product-кода.

и SHA указываются отдельно в итоговом сообщении сессии.
