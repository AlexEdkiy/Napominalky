## План переноса и условия переключения

1. Получить SSH-доступ и проверить архитектуру, диски/RAM, Docker, существующие
   сайты, занятые порты, firewall и способ управления nginx на 195.206.252.160.
   `3dsotky.ru` и другие проекты должны продолжать работать. Не заменять общий
   nginx.conf и не останавливать чужие контейнеры.
2. Перенести проверенные неизменяемые app/landing артефакты и закреплённые образы;
   проверить хеши и платформу. Настроить отдельные сети, тома PostgreSQL/Redis и
   loopback-порты API/web. Не использовать main/control как новый app release:
   там есть ещё не выпущенная проверка почты MOB-74.
3. Подготовить виртуальные хосты lk/www/apex и TLS с продлением. Сертификаты и
   private keys передавать только по SSH, вне Git, с ограниченными правами;
   предварительно сохранить текущую конфигурацию целевого хоста. Проверить
   маршруты через `curl --resolve` до DNS. Лендинг пока остаётся заглушкой 503.
4. Сохранить старый API `/napominalki/api/v1/` на jemsoft.ru: APK 1.0.8 (52)
   использует его. На jemsoft также есть `/sub`, `/mafin-recovery` и другие
   маршруты. Смена A-записи всего jemsoft требует подготовленного виртуального
   хоста: Напоминалки → новый локальный backend, прочие пути → прежний сервер
   с проверенным HTTPS/SNI. Сначала проверить доступность этого upstream с нового
   сервера. Альтернатива — отдельный выпуск APK с новым API, но он сам по себе
   не восстановит уже установленные приложения. Маршруты прочих проектов
   и DNS jemsoft до этой проверки не менять.
5. Проверить новый runtime на отдельной тестовой БД с фикстурами. Для финального
   переноса приостановить источники записи Напоминалок (API, scheduler, workers,
   если обнаружены), сделать согласованный pg_dump только reminders и снимки
   storage/Redis. Сохранить APP_KEY, токены, ID, timestamps, tombstones и порядок
   пунктов; не запускать миграции. Бэкапы держать вне Git с правами 0600/0700.
6. Восстановить данные в выделенные новые тома, проверить таблицы/счётчики и
   критические связи, права файлов и отсутствие двух активных schedulers.
   Проверки production ограничить безопасным чтением и контрактными smoke;
   тестовые пользовательские записи не создавать в перенесённой рабочей БД.
7. Направить прежние адреса Напоминалок на единственный активный backend нового
   сервера до возобновления записи. Затем изменить `lk`, `@`, `www` в зоне
   napominalky.ru на 195.206.252.160; jemsoft переключать только после п.4.
   Это исключает две расходящиеся базы во время DNS-кэширования. Подтвердить
   TLS/API/web внешними узлами РФ и домашней/мобильной сетью пользователя.
8. Старый сервер/релиз и финальный бэкап сохранить для отката. До первого нового
   изменения можно вернуть прежний backend. После возобновления записи на новом
   сервере откат маршрутов не должен возвращать старую БД: требуется обратный
   перенос актуальных данных с новой паузой записи либо проксирование на новый
   backend. Не запускать прежние legacy-контейнеры с устаревшим storage.

Ближайшая зависимость — SSH-доступ к целевому серверу, пользователь создаст отдельную учётную запись позднее. Затем — конкретизация
портов, nginx и DNS-переключения по результатам инвентаризации. DNS и работающие
сервисы пока не менялись. Восстановление не подтверждено; OPS-18 остаётся
in_progress до внешних проверок и проверки на подключении пользователя.
