## Изменения

- Адрес веба: `https://lk.napominalky.ru/`, без префикса `/napominalki/`.
- Immutable-артефакт содержит две сборки из одного SHA: корневую и прежнюю.
  API корневой сборки — `/api/v1`; router, offline-worker и публичные ресурсы
  используют соответствующий base. Telegram получает новый публичный адрес.
- Внешний nginx: отдельный vhost, API на тот же backend, TLS отдельным сертификатом.
  Шаблон: `deploy/lk.napominalky.ru.nginx.conf`.
- Старый `https://jemsoft.ru/napominalki/api/` сохраняется без перенаправления:
  им пользуются выпущенные APK. Новая мобильная сборка для переноса веба не требуется.
- Миграций БД и изменения пользовательских данных нет. На новом origin нужно
  заново войти: токены из localStorage старого домена не переносятся через URL.

## Порядок включения

1. DNS у NIC.RU: A `lk.napominalky.ru → 94.103.15.24`, TTL 600. Проверить
   authoritative и публичные DNS; AAAA не должен вести на другой сервер.
2. Сохранить копию внешнего nginx и добавить HTTP vhost с webroot ACME.
   Проверить конфигурацию и challenge через Host header. Старые сайты не менять.
3. После появления DNS выпустить отдельный сертификат webroot для
   `lk.napominalky.ru`. Существующий cron certbot renew обслуживает все сертификаты
   и перечитывает nginx; проверить продление нового сертификата через dry-run.
4. Проверить точный SHA: web/types/tests, release tests, CI, immutable manifest,
   оба base в nginx и браузере (desktop/mobile, login, deep links, offline/recovery).
5. Добавить HTTPS vhost, переключить проверенный артефакт через `switch.py`.
   В production `.env` обновить только `APP_URL`/`FRONTEND_URL` на новый HTTPS-адрес,
   сохранив закрытую резервную копию вне Git. Не печатать секреты.
6. Проверить публичные SPA/JS, `/api/v1/auth/me` 401, пустой login 422, TLS и старый
   API; только затем менять основной адрес public probe в production/target.json.
   Старые HTML-ссылки можно перенаправить, сохраняя API и статические offline-ресурсы.

Live nginx — файл, смонтированный в контейнер отдельно: записывать содержимое
на месте, не заменять inode. Перед записью сравнить с сохранённой версией;
при ошибке `nginx -t`/reload вернуть исходное содержимое.

## Откат

Сохранить proxy/env/target до переноса вне Git. Для возврата к `r57d35d7-dev26`
сначала восстановить прежние proxy/env/target (старый артефакт не содержит root
bundle), затем выполнить managed switch на этот артефакт. БД не откатывать.
Не удалять сертификаты, пользовательское storage или существующие Docker-сети.
