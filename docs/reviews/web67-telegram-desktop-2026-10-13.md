Состояние: реализация; выпуск учитывается отдельно.

## Изменение

По просьбе пользователя иконка Telegram на сайте копирует полный текст и вызывает
зарегистрированное приложение через `tg://` в текущей вкладке (`_self`). Telegram Web
больше не открывается основным действием. Содержимое не передаётся в URI: после запуска
пользователь выбирает чат и вставляет текст. Прежние формат заметки, статусы/отметки
пунктов и количества сохранены.

Запись clipboard начинается перед запуском внешнего приложения, оба вызова происходят
непосредственно в обработчике клика, до await. Это сохраняет фокус при начале копирования
и пользовательскую активацию при вызове протокола. Веб-форма/черновик не закрываются.

После действия доступны «Открыть приложение» для повторного запуска и отдельная
ссылка «Telegram Web». Автоматического перехода на Web по таймеру, blur или null-ответу
браузера нет. Если clipboard недоступен, остаются полный выделенный текст и ручное
копирование. Интерфейс подтверждает только копирование, а не запуск приложения.

Telegram использует [обработчики tg: в ОС](https://core.telegram.org/api/links).
Проверены официальные исходники [Desktop Application](https://github.com/telegramdesktop/tdesktop/blob/dev/Telegram/SourceFiles/core/application.cpp)
и [обработчики ссылок](https://github.com/telegramdesktop/tdesktop/blob/dev/Telegram/SourceFiles/core/local_url_handlers.cpp):
внешняя ссылка активирует окно; пустая команда не выбирает чат и не меняет настройки.
Запуск зависит от установленного клиента, зарегистрированного обработчика и разрешения
браузера. Приложение сайта не меняет ассоциации протоколов ОС. На мобильном web тот же
протокол передаётся установленному мобильному Telegram; native APK не меняется.

## Проверки

- 77 web-файлов / 728 тестов прошли. Целевые компоненты — 83 теста. После уточнения
  типизации теста финальный повтор share-компонента — 10 тестов прошли.
- Vue typecheck и production build прошли. Проверены последовательность copy → tg:,
  текущая вкладка, отсутствие OS share и автоматического web-fallback, ручное копирование,
  недоступный обработчик/ошибка открытия, отсутствие ложного подтверждения запуска,
  длинный текст/черновик и неизменность данных задачи/покупок.
- В первой сборке выявлен только типовой дефект теста: wrapper.get() исключает exists()
  из своего TS-типа. Проверка заменена на содержимое ссылки, production-код не менялся.
- Доказательства: `/home/vselug/workspace/Napominalky-artifacts/web67/`.

Физический Windows/Telegram Desktop в среде отсутствует: фактическое появление окна
и вставка в настоящий чат не объявляются проверенными. Браузер может попросить
разрешение открытия приложения; при отсутствии клиента доступна явная ссылка Web.
