## Поведение

При потере сети или сетевой ошибке API появляется экран «Что-то пошло не так.
Проверьте подключение к интернету» с кнопкой «Попробовать снова». Фон — исходный
`mobile/assets/onboarding-illustration.png`, скопированный побайтно в web; изображение
не перерисовывалось. Один дизайн используется на desktop, mobile web и при offline reload.

Проверка связи — отдельный GET к существующему `/api/v1/auth/me` без токена, вне
перехватчика авторизации. JSON 200/401 подтверждает доступность; HTML captive portal,
ошибка сервера или таймаут не снимают экран. Таймаут 6 секунд, параллельные проверки
объединяются. Событие `online` запускает проверку автоматически; одной декларации
браузера о наличии сети недостаточно. Устаревший успешный ответ после нового обрыва
игнорируется. Отмена поиска, 401, 422 и другие HTTP-ответы сохраняют прежнюю обработку.

Экран открывается в native modal dialog поверх смонтированного приложения. URL,
авторизация и черновики форм сохраняются; фон недоступен для кликов/клавиатуры, Esc
не закрывает спрятанную форму. Blur названия задачи/пункта при передаче фокуса экрану
ошибки не выполняет автосохранение и не сбрасывает черновик. После восстановления
перечитывается состояние ЛК существующим read-only механизмом; неудавшиеся изменяющие
запросы автоматически не повторяются. Обычная ручная перезагрузка по-прежнему теряет
несохранённые формы: отдельное долговременное хранение web-черновиков не добавлялось.

Обрыв при первой загрузке ленивого маршрута также показывает экран ошибки. Если ни
один маршрут ещё не смонтирован, после восстановления выполняется одна защищённая
от цикла перезагрузка документа: черновика в таком состоянии ещё нет.

## Offline-перезагрузка и границы кеша

Service worker действует только в scope приложения (production `/napominalki/`).
После первого успешного онлайн-посещения он сохраняет ровно четыре публичных файла:
`offline.html`, `connection.css`, `connection-illustration.png`, `offline-retry.js`.
Навигация сначала идёт в сеть; только транспортная ошибка возвращает готовый экран
по исходному URL. API, POST/PUT/DELETE, JS приложения, storage и другие сайты/разделы
не перехватываются и не кешируются. Удаляются только старые версии собственного кеша.
В статический fallback вставляется base приложения: глубокие ссылки работают и офлайн.
После изменения публичных файлов fallback нужно увеличивать версию кеша в worker.

Это узкий offline fallback, а не офлайн-хранилище задач. При самом первом посещении
без интернета либо при недоступном Service Worker/Cache Storage браузер не может
заранее получить эти файлы; в уже загруженной SPA экран работает и без worker.
Механизм следует [network-first fallback Service Worker](https://developer.mozilla.org/en-US/docs/Web/API/Service_Worker_API/Using_Service_Workers);
реальный GET дополняет [ненадёжный индикатор navigator.onLine](https://developer.mozilla.org/en-US/docs/Web/API/Navigator/onLine).
