# DEV-26 / ARCH-8: удаление списка после удаления пунктов

Ветка выпуска `release-dev26` основана на `d418d59`; backend до исправления совпадал
с production `3bb319c`. MOB-74 в выпуск не включена. Пользователь разрешил выпуск
2026-10-29 сообщением «выпускай» после диагностики WEB-70.

## Изменение

Серверный пересчёт по пунктам больше не выдаёт себя за новую прямую правку родителя
при проверке удаления. Приватный `user_updated_at` ведётся моделью при обычном save;
пересчёт сохраняет его. Публичные `updated_at/server_revision` продолжают доставлять
вычисляемые поля текущему APK. Реальная более новая правка родителя сохраняет
приоритет и резервную копию конфликта. Для остальных мутаций LWW не меняется.

[Решение и совместимость](../architecture/list-deletion-clock.md).
Миграция только добавляет/заполняет служебную колонку. Автоматического восстановления
или повторного удаления исторических пользовательских записей нет.

## Самопроверка

- Исходный код: 6 регрессий воспроизвели отказ удаления/подмену версии родителя.
- Backend: из неизменяемого артефакта — **465 тестов / 2142 assertions**;
  целевой файл — 11 тестов / 98 assertions.
- Mobile: 1191 тест, typecheck; 9 отдельных интеграционных сценариев с настоящими
  Laravel/PostgreSQL, Node SQLite, production repositories, outbox, push/pull и
  SyncSession. Экранные чтения проверены через те же repositories.
- Интеграция: 23 пункта с manual/auto статусом, 501 пункт и разбиение по 500,
  покупки, очередь до отправки, commit с потерянным ответом и повтором, tombstone
  на другом клиенте и отсутствие в web API; новая локальная правка во время запроса;
  получение вычисляемого статуса; более новая REST-правка другого устройства;
  запоздалый ack после logout/account switch не очищает очередь и не пишет в новую БД.
- Backend дополнительно проверяет auto/manual статус и даты с 501 пунктом,
  защиту tombstone от старого update/delete, запрет подмены служебной метки в payload,
  неизменность содержимого/тombstone/ревизий при backfill, скрытие метки из pull.
- Скрипты выпуска: 3 регрессии; diff check. Зависимости не меняются.
- Нативные Expo-модули заменены тестовыми адаптерами; это не E2E на телефоне.
  Независимое ревью не выполнялось. Новый APK не требуется.

Для воспроизведения интеграции нужна отдельная PostgreSQL `reminders_test` и API
на loopback: после `php artisan test` выполнить `php tests/Support/seedSyncIntegration.php`,
запустить API и выполнить в mobile:
`SYNC_INTEGRATION_URL=http://127.0.0.1:18026 npm test -- --runInBand listDeletionBackend.integration.test.ts`.
CI выполняет эту проверку в backend job; обычный mobile job пропускает opt-in suite.
Клиентский адаптер запрещает внешний URL, seeder запрещает production и другую БД.

Существующее ограничение: обычное обновление родителя по-прежнему может конфликтовать
с вычисляемой серверной версией. DEV-26 меняет только удаление; остальные конфликты,
точность времени и гарантии sync v2 остаются в DEV-24. Исторический конфликт не
исправляется по догадке; WEB-70 завершён отдельно по подтверждённому намерению владельца.
