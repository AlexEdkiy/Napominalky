# WEB-64 — красный будильник по дедлайну

Дата: 2026-10-03. Ветка: `manage-2026-09-30`. Самопроверка Codex.

## Поведение

Уточнение пользователя заменяет условие из WEB-58: красный будильник рядом с
задачей/покупками на главной означает **дедлайн на сегодня**. После переноса срока
на будущую дату и успешного обновления данных с сервера значок исчезает. Поле
`reminder_at` не участвует в этом индикаторе. Если другой невыполненный пункт
по-прежнему имеет дедлайн на сегодня, значок остаётся.

`LkOverviewTasksPanel` использует существующий `hasDeadlineToday`; подпись и
accessibility label теперь «Дедлайн на сегодня». Неиспользуемый `hasScheduleToday`
удалён. API, сервер, данные, mobile и механизм синхронизации не изменены. Изменение
не меняет время уведомлений и не связывает два поля расписания автоматически.

## Проверки

- До исправления три проверки воспроизводили ошибку: напоминание удерживало
  будильник после переноса дедлайна.
- 709 web-тестов / 75 файлов прошли. Новые регрессии монтируют настоящий
  `DashboardView`, вызывают `useSyncMeter().runSync()` и получают новые REST-данные
  без размонтирования страницы. Проверены tasks/goods, выполненный пункт и второй
  невыполненный пункт с сегодняшним дедлайном.
- Production-сборка с `VITE_API_URL=/napominalki` и base `/napominalki/` прошла,
  включая `vue-tsc --noEmit`.
- Chromium 1365, 390 и 320 px, часовой пояс Europe/Moscow: до переноса два
  будильника, после автообновления при возврате на вкладку — ноль. Страница не
  перезагружается, горизонтального переполнения и page errors нет. Скриншот mobile
  просмотрен. HTTP-ответы тестовые, пользовательские данные не использовались.
- Со стороны mobile использована проверка MOB-71 на том же коде: реальный экран,
  hooks, SQLite/outbox и исходящий sync payload отдельно сохраняют дедлайн и
  напоминание. Это Node SQLite/native mocks, не проверка физического телефона.
