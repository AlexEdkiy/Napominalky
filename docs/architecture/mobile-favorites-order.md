# ARCH-7: Избранное и порядок пунктов

Дата: 2026-10-15. Область: MOB-75 / MBE-25. Самопроверка автора.

Пользователь подтвердил избранное всех записей с синхронизацией и перетаскивание за ручку.

## Контракт

Добавляем `is_favorite` boolean NOT NULL default false в notes, shopping_lists,
shopping_list_items, reminders на сервере и integer 0/1 в SQLite каждого профиля.
Это независимый признак: прежний `is_pinned` заметок сохраняет назначение и данные.
Sync принимает поле 0/1/boolean и возвращает boolean. Старые клиенты, не отправляющие
поле, не сбрасывают его. Pull старого сервера без поля также не стирает локальное
избранное. CRUD сайта сохраняет неизвестное ему поле. Новые строки по умолчанию
не избранные; миграции не изменяют updated_at, курсоры и outbox прежних записей.

Звёздочка меняется атомарно вместе с полным снимком outbox, по текущей строке БД,
а не устаревшему состоянию UI. Репозиторий фиксирует базу владельца в начале операции.
Гостевой профиль остаётся изолированным; его избранное не переносится в аккаунт.
При попытке использовать UUID чужого аккаунта сервер отклоняет весь push с 422;
чужие данные не выдаются, очередь клиента не подтверждается. Это заменяет прежнюю
ошибку уникального индекса (500) без передачи записи другому владельцу.
Существующая LWW-семантика целой записи остаётся; более поздняя полная правка побеждает.

## Порядок и количество

Избранное выше остальных внутри выбранного фильтра. Главная сохраняет разделы по типам;
в напоминаниях избранные выделяются первой секцией текущего фильтра. Поиск сортирует
избранное до пагинации; календарь — внутри выбранного дня. Закрепление заметок вторично.

Перетаскивание меняет существующий `position` пунктов, не признак избранного.
Перемещение ограничено текущей группой избранного. При фильтре выполненности меняются
только слоты видимых пунктов, скрытые остаются на местах. Все новые позиции и outbox
фиксируются одной локальной транзакцией; удалённые/чужие пункты не восстанавливаются.
Сервер принимает прежний position, при одинаковых позициях UUID даёт стабильный порядок.
Частичная доставка >500 правок может временно показать промежуточный порядок до следующего
батча — это ограничение существующего контракта, не потеря элементов.

Количество покупки всегда видно, включая 1; кнопка увеличивает последнее сохранённое
значение в транзакции, чтобы быстрые нажатия не терялись. Минимум 1.

## Интерфейс и выпуск

Используем установленный RN 0.81 PanResponder/Animated для ручки без новых зависимостей;
автопрокрутка у края, отмена жеста при смене данных/экрана, доступные действия выше/ниже.
Системная строка редактора использует контраст темы и safe area. Светлый стиль главной
не должен оставаться активным на светлом редакторе.

Сначала серверная миграция и API, затем APK. В ветке есть невыпущенная MOB-74:
выпуск зависит от готовности SMTP/подтверждения почты и не выполняется автоматически.
Полные тесты и Android export не заменяют проверку жестов/статус-бара на устройстве.

Документация API: [Expo SDK 54 StatusBar](https://docs.expo.dev/versions/v54.0.0/sdk/status-bar/),
[RN 0.81 PanResponder](https://reactnative.dev/docs/0.81/panresponder).
