# ARCH-6: подтверждение почты новых аккаунтов

Дата: 2026-10-14. Пользователь подтвердил обязательность проверки новых аккаунтов.

- Аддитивная миграция `users.email_verification_required`, default false: существующие
  аккаунты продолжают входить, но не получают фиктивного `email_verified_at`.
  Регистрация выставляет флаг true. До подтверждения токены не выдаются; дополнительная
  проверка на защищённых API закрывает доступ даже с ранее созданным токеном.
- `POST /auth/register`: 201, `data: {verification_required: true, email, email_sent,
  message}`. Пароль хешируется как прежде. Токен/профиль в ответ не входят.
  Mobile и web показывают ожидание письма, сохраняют пароль только в памяти формы.
  Старым APK для новой регистрации потребуется обновление; существующий вход совместим.
- `POST /auth/login`: существующий контракт успеха; правильный пароль неподтверждённого
  нового аккаунта возвращает 403 `code: email_verification_required`, русское сообщение.
  Гостевая SQLite не присваивается аккаунту, до успешного входа хранилище не переключается.
- `POST /auth/email/resend`: email/password, тот же парольный контроль, ограничение IP
  и адреса, не чаще раза в минуту. Неверные данные не раскрывают наличие аккаунта.
  Ошибка транспорта не сообщает об успешной отправке и позволяет повторить её.
- Письмо на русском, ссылка на публичную страницу `/verify-email` сайта.
  В параметре находится относительный Laravel signed URL (UUID + хеш email), срок 60 минут.
  Относительная подпись учитывает удаление `/napominalki` обратным прокси. Публичный
  адрес берётся из `app.frontend_url`, не из Host запроса или production APP_URL=localhost.
- GET страницы ничего не активирует (защита от сканеров писем). Кнопка вызывает POST
  по подписанному API URL без требования авторизации. Проверяются подпись, срок,
  актуальный email и активность аккаунта. Повтор действующей ссылки идемпотентен.
  Страница не входит автоматически: после подтверждения пользователь вводит пароль.
- Синхронная отправка через Laravel Notifications, как существующее восстановление
  пароля; отдельного queue worker нет. В production log/array не считаются доставкой.
  До настройки рабочего почтового транспорта выпуск обязательной проверки запрещён,
  иначе новые пользователи не смогут завершить регистрацию. SMTP-секреты вне Git.
- Проверки: серверный HTTP/Notification fake, реальный рендер письма, сроки/подписи/
  повторы/ограничения/ошибки SMTP; RN формы и хук с SQLite; веб-форма и страница ссылки.
  Проверка SMTP-доставки и физического APK учитывается отдельно.

Основа: [Laravel VerifyEmail](https://api.laravel.com/docs/12.x/Illuminate/Auth/Notifications/VerifyEmail.html)
и [Laravel Notifications](https://laravel.com/framework/docs/12.x/notifications).
