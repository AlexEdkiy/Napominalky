# ARCH-8: версия удаления родительского списка

DEV-26, 2026-10-29. Реализация для действующего sync v1, совместимая с ARCH-4.

Mobile deleteList ставит в outbox tombstone каждого пункта, затем списка. Пересчёт
статуса/дат после удаления пункта меняет updated_at списка на серверное время.
Поэтому обычный LWW отклонял исходное удаление родителя, даже в одном push.
Перестановка изменений не решает разделение очереди по 500 записей.

Добавляется приватная nullable timestamp-колонка shopping_lists.user_updated_at.
При обычном save она получает updated_at прямой мутации (клиентское время в sync,
серверное в REST). RecalculateListStatusAction вызывает saveDerivedState: сохраняет
этот маркер, но продолжает менять updated_at и server_revision для доставки
вычисляемых полей старым мобильным клиентам. Маркер не принимается из payload
и не сериализуется в API.

Только delete активного списка сравнивается с user_updated_at, с консервативным
fallback на updated_at при null. Все прочие сущности/операции и уже удалённый
родитель используют прежний LWW. Настоящая более новая правка родителя продолжает
побеждать старое удаление и сохраняет конфликт. REST soft-delete обходится без
saving; для tombstone сравнение остаётся по updated_at, поэтому это безопасно.
Новая правка пункта сравнивается по версии самого пункта, как и раньше; изменение
пункта не становится неявной пользовательской правкой родительской карточки.

Простое сохранение прежнего updated_at при пересчёте отклонено: старый APK применяет
pull по updated_at, а legacy PostgreSQL/Eloquent хранят секунды при миллисекундах
в SQLite. Это могло бы удерживать прежние вычисляемые поля после мобильной правки.
Точность общего LWW и редизайн подтверждений остаются в DEV-24.

Миграция заполняет маркер существующим updated_at, не меняет содержимое, tombstone,
публичные метки или ревизии и не восстанавливает прошлые конфликты автоматически.
Исторические пустые карточки требуют отдельной проверки намерения пользователя.

Выпуск: backup → краткая остановка записей → миграция → immutable switch → проверки.
Откат к прежнему коду сохраняет колонку, down в production не выполнять. Если старый
код работал после отката, перед повторным включением нового кода при остановленных
записях повторить backfill user_updated_at = updated_at: старый код не ведёт маркер.
API/SQLite/APK не меняются. Независимое ревью не выполнено; проверки — самопроверка.
