# MOB-69 — поиск в мобильном приложении

Дата: 2026-10-02. Следующий этап после [WEB-62](web-search.md).

Поиск доступен через кнопку «Искать везде» в раскрытом поиске шапок основных разделов.
Существующая фильтрация раздела остаётся; поиск по всему открывает `/search` с введённым
запросом. Экран хранит запрос/тип/страницу в своём состоянии при переходе к объекту и назад.
Типы: задачи/покупки, пункты, заметки, напоминания; результаты по 20, название/фрагмент,
отметки выполнения/архива, буквальная подсветка. Запрос 2–200 символов, отправка кнопкой
или клавиатурой. Для пункта передаётся itemUuid; его шторка атрибутов или комментариев
открывается в существующем экране списка. Мутации идут через существующие обработчики.

Источник — локальная SQLite текущего профиля, включая ещё не отправленные изменения.
Никаких HTTP-запросов для поиска; серверные данные появляются после обычной синхронизации.
SearchRepository читает неудалённые доменные таблицы через Drizzle и проверяет родителя
пункта/комментария. Совпадения в нескольких комментариях дают один пункт. Поля аналогичны
WEB-62: title/body, title/tags, name/comment/tags/тред, title/notes. Архив и выполненные
включены. Сначала совпадение названия, затем updatedAt и стабильные type/uuid.

SQLite без ICU не гарантирует lower/LIKE для кириллицы. В первой версии сопоставление
делается в JS через Unicode toLowerCase/includes, после ограниченной собственностью и
soft-delete выборки SQLite. Это сканирование локальных текстов без индекса; не морфология.
Новых native-зависимостей, SQL-функций, миграций и изменений outbox/sync нет. Масштабирование
на очень большие базы требует отдельного замера и поискового индекса.

Локальные sync-строки могут иметь userId=null: принадлежность базы определяется
LAST_USER_ID/reset при смене аккаунта. Поиск не должен выдавать такую базу гостю или
другому известному пользователю. Строки с явным чужим userId исключаются дополнительно.
Кеш поиска живёт только при открытом экране, привязан к сессии; без гостя/токена поиск
недоступен. Экран обновляет поиск при возвращении и после событий SQLite по доменным
таблицам, включая pull. Запоздалые результаты предыдущего запроса/сессии не отображаются.

Проверки: настоящий SQLite с установленным Expo Drizzle через существующий Node bridge,
отдельно RN-компоненты/переходы и события БД, typecheck/CI. Эти проверки не выдаются за
установку APK и тестирование клавиатуры/жестов на физическом телефоне.
