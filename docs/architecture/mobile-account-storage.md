# ARCH-5 — владельцы локальных данных mobile

2026-10-14. Реализация MOB-73 по запросу пользователя. Самопроверка автора.

Проблема: SecureStore удаляет токен через 24 часа, хотя серверный Sanctum имеет
настраиваемое ограничение (по умолчанию 30 дней). Гостевой вход открывает прежнюю
SQLite; повторный вход другого пользователя удаляет её, включая локальные правки.

Каждому аккаунту и гостю соответствует отдельный файл SQLite с прежней схемой.
Владелец существующего `napominalki.db` определяется по `last_user_id` и закрепляется
однократно в sync_meta. Файл используется на прежнем месте, без переноса строк,
удаления outbox или переименования при обновлении. При отсутствии владельца и
признаков аккаунта это гостевая база. Неопределённые данные аккаунта не выдаются гостю.
Остальные владельцы получают отдельные файлы. Миграции выполняются в каждом файле.

Гостевые данные остаются гостевыми даже после авторизации. Автоматическое присвоение
гостевых данных аккаунту из ARCH-4 §4.3 отменяется настоящим запросом пользователя.
Импорт в аккаунт — отдельная будущая явная операция, не часть этого исправления.
Выход больше не удаляет локальные записи и не требует согласия на их потерю.
Аккаунтные данные снова доступны только после входа соответствующего пользователя.

Срок токена определяет сервер: локального таймера удаления нет. Вне сети действующая
локальная сессия продолжает работать. Авторизованный 401 закрывает сессию, останавливает
sync и показывает повторный вход. Истечение не превращает данные аккаунта в гостевые.
SecureStore сохраняет идентификатор владельца рядом с токеном, профиль остаётся в SQLite.

При смене сессии экраны данных закрываются, Query cache очищается, sync отменяется
и дожидается завершения, затем выбирается готовая БД. Репозиторная операция и sync-цикл
держат конкретное соединение до завершения; запоздалые ответы не пишут в новую базу.
Старые уведомления отменяются; запускаются только уведомления выбранного владельца.
Ответы на уведомления другого владельца игнорируются. Закрытые соединения не нужны:
держим использованные подключения открытыми до завершения процесса, чтобы запоздалая
локальная операция могла безопасно закончиться в исходной базе.

API, SQL доменных таблиц, tombstones, UUID, LWW и формат outbox не меняются. Это
изоляция доступа внутри приложения, а не шифрование файлов от владельца/root устройства.

Проверки: реальные SQLite и installed Expo Drizzle, login/guest/logout/401/restart,
несколько владельцев, поиск и outbox, отмена sync в полёте; native storage/HTTP/OS
notifications заменяются адаптерами. Физическая установка проверяется отдельно.

API сверены с [Expo SQLite SDK 54](https://docs.expo.dev/versions/v54.0.0/sdk/sqlite/)
и [Expo Router protected routes](https://docs.expo.dev/router/advanced/protected/).
