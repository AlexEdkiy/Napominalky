# WEB-54 — общие даты задачи

Решение для запроса 2026-09-30. Применяется только к type=tasks.
Пользователь уточнил: в пересчёте участвуют только невыполненные пункты.

## Контракт

В shopping_lists добавляются nullable deadline (date) и reminder_at
(datetime): это сохраняемые итоговые значения. REST create/update принимает эти
же поля как выбранную пользователем общую дату. Ответ REST и sync pull содержит
итоговое значение после пересчёта; отсутствующее поле при update ничего не очищает,
явный null очищает общую настройку.

Внутренние manual_deadline / manual_reminder_at хранят общую настройку отдельно
от результата. Они не доступны массовому присвоению из API/sync. Итог каждой даты —
минимум из общей настройки и соответствующих дат неудалённых пунктов с
is_checked=false. Просроченные даты также участвуют; даты и напоминания считаются
независимо. Времена сравниваются как абсолютные моменты, дата дедлайна — YYYY-MM-DD.

Пример: общий срок 15.10.2026, активный пункт 12.10.2026 → API/таблица показывают
12.10.2026. После завершения/удаления этого пункта возвращается 15.10.2026, если нет
другого более раннего активного пункта. Без общей настройки итог выводится из пунктов;
без обоих источников возвращается null. Перенос общей даты позже раннего пункта
не меняет дату самого пункта. Удаление общей настройки тоже не очищает пункты.

Пересчёт выполняется при изменении задачи и при create/update/check/delete пунктов,
включая sync push. Ручной статус задачи не блокирует пересчёт дат. Изменение итоговых
дат родителя получает server_revision для последующего pull. Запись пункта и
пересчёт входят в одну транзакцию; пересчёт сериализуется блокировкой родителя.
Sync-обновление самого списка также читает его под этой блокировкой.
Глобальный порядок всех sync writers остаётся отдельной DEV-24/B.

## Совместимость и выпуск

Миграция добавляет nullable колонки и заполняет итоговые даты существующих задач из
активных пунктов с обновлением sync revision. Покупки не участвуют. Старые мобильные
клиенты игнорируют дополнительные поля pull и не посылают их при обычном push:
общая настройка не должна стираться. Проверить на настоящих mobile mappers/SQLite/outbox
и backend HTTP round-trip. Новый mobile UI общих дат и нативное планирование общего
напоминания не входят в этот web-запрос; прежние напоминания отдельных пунктов сохраняются.

Сначала миграция/backend, затем web. Старый код совместим с расширенной схемой; при
откате кода колонки сохраняются, down в production не выполняется. Перед выпуском
проверить изолированный backend, web typecheck/tests/build и UI в браузере.

## Таблица

Только наименование task открывает форму. Статус, теги, дедлайн и дата/время
напоминания редактируются по месту, с отменой, видимой ошибкой и защитой от повторной
отправки. После сохранения отображается ответ API, в том числе дата раннего пункта.
Подсказка над счётчиком пунктов показывает названия пунктов (включая выполненные
с отметкой), без текста комментариев. Для goods сохраняется прежнее поведение.
