# WEB-62 — поиск в личном кабинете

Решение 2026-10-02 до реализации. Пользователь подтвердил поиск по названиям и
тексту задач, покупок, пунктов, заметок и напоминаний. Новых таблиц/миграций нет.

## Контракт

`GET /api/v1/search?q=текст&type=all&page=1&per_page=20`, Sanctum и отдельный throttle поиска: 60 запросов в минуту на пользователя.
`q`: строка после trim, 2–200 символов; `type`: all/list/item/note/reminder;
`page` >= 1; `per_page` 1–50. Ошибки параметров — стандартный 422, гость — 401.
Ответ: стандартные `data`, `meta`, `links`. Строка результата:
`type`, `uuid`, `title`, `excerpt`, `list_uuid`, `list_title`, `list_type`,
`is_completed`, `is_archived`, `updated_at`; неприменимые поля — null/false.
Внутренние id/user_id и полные тела записей наружу не передаются.

Поиск — буквальная подстрока без учёта регистра (в том числе кириллица), а не
язык операторов/морфология. `%`, `_`, `!` экранируются; ввод передаётся параметром SQL.
Поля: title/body заметки; title/tags списка; name/comment/tags пункта и body его
неудалённых комментариев; title/notes напоминания. Архивные/выполненные включены
и отмечены. Удалённые записи и пункты удалённого списка исключены.
В каждой ветке запроса проверяется user_id; у пункта также владелец родителя,
у комментария — владелец комментария, пункта и родителя.

Четыре SQL-выборки объединяются UNION ALL; пагинация выполняется сервером.
Один пункт с несколькими совпавшими комментариями возвращается один раз.
Порядок: совпадение в названии выше совпадения в тексте; затем updated_at desc,
тип и UUID для стабильной пагинации. Фрагмент до 240 символов вокруг совпадения.
В первой версии без отдельного поискового индекса; стоимость ограничена данными
пользователя, размером страницы и throttle. Изменение индексов — отдельно после
измерений на реальном объёме, текущий поиск заметок и sync не меняются.

## Web

Защищённый маршрут `/lk/search?q=...&type=...&page=...`. Enter/кнопка «Найти»
в общей шапке открывают его на desktop/mobile. На странице — форма запроса,
фильтр типа, число результатов, карточки с типом/фрагментом, постраничная навигация.
Новый запрос отменяет старый HTTP; номер запроса и размонтирование защищают UI от
позднего ответа. Пустой/короткий ввод не отправляется. Текст выводится Vue без v-html.

Результат загружает запись через существующий авторизованный GET и открывает
центральную форму поверх поиска; URL и выдача сохраняются. Для пункта дополнительно
раскрывается и прокручивается соответствующая строка. Удалённый после поиска
результат показывает ошибку открытия и позволяет повторить поиск.

Проверки: изоляция двух пользователей/удалений, кириллица и спецсимволы, полный
набор типов/тексты/комментарии, пагинация и ранжирование, валидация, web history,
гонки запросов/ошибки, открытие результатов и мобильная верстка. Только отдельная
PostgreSQL БД и HTTP-фикстуры для браузера; production-данные не используются.
